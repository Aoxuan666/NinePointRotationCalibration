# 视觉工作站上位机 TCP 通讯接口规范

> 协议版本：v1.1（由 v1.0 修订，融合 ZM910A 上位机补充需求）  
> 修订日期：2026-11-23  
> 适用系统：视觉工作站（TCP Server） <-> 上位机控制系统（TCP Client，ZM910A 双吸嘴双 R 轴）

---

## 1. 通讯架构与职责边界

本规范面向 ZM910A PCB 移栽龙门机构：**左、右两个吸嘴共用一套 X/Y 轴，各有一根独立 R 轴**（`Left` 对应 `R1`，`Right` 对应 `R2`）。

| 角色 | 通讯身份 | 职责范围 |
| --- | --- | --- |
| **视觉工作站** | TCP Server（默认监听 `0.0.0.0:9100`，单客户端连接） | 相机控制与取图、模板定位、左/右吸嘴独立 9+5 标定求解与持久化、PCB 瑕疵检测与空料识别、左/右吸嘴独立目标坐标与双 R 轴角度映射 |
| **上位机** | TCP Client | X/Y/R1/R2 轴运动控制、标定会话原点锁存、到位停稳判定、软限位与安全互锁、标定拒动/中止、R 轴超行程判定、吸取/贴装动作执行与整机报警/清料决策 |

---

## 2. 传输协议与通用约定（标准 JSON 格式）

### 2.1 帧格式与编码

- **TCP 帧结构**：`[4 字节无符号大端整数 N] + [N 字节 UTF-8 JSON 数据]`，`N` 仅包含 JSON 负载字节数。
- **最大帧长**：默认 `1 MiB (1048576 字节)`。长度为 `0`、超限、非合法 UTF-8 或 JSON 格式错误时，服务端将直接断开连接并记录协议错误。
- **数值与时间**：所有数字使用标准 JSON number（小数点固定为 `.`），禁止 `NaN` / `Infinity`；时间戳采用 UTC ISO-8601 格式。

### 2.2 统一消息包络

所有收发报文均采用统一的 JSON 包络格式：

```json
{
  "version": "1.1",
  "messageId": "6f26388d0d214fbd9c8a37a6dd434270",
  "correlationId": null,
  "type": "inspection.trigger",
  "timestampUtc": "2026-11-23T08:00:00.0000000Z",
  "data": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `version` | string | 是 | 协议版本号，v1.1 固定为 `"1.1"`（视觉端向下兼容接收 `"1.0"`） |
| `messageId` | string | 是 | 发送方生成的唯一消息 ID。同一次 TCP 连接内不可重复，重复发送会返回 `system.error / DUPLICATE_MESSAGE`；失败重试必须重新生成新 ID |
| `correlationId` | string/null | 条件必填 | **所有应答和结果报文必填**，值须等于对应请求报文的 `messageId`；主动发起的请求或状态推送通知填 `null` 或 `""` |
| `type` | string | 是 | 消息类型，统一采用**小写点分格式**（如 `inspection.trigger`） |
| `timestampUtc` | string | 建议 | UTC ISO-8601 时间戳 |
| `data` | object | 是 | 业务数据体，无字段时传 `{}` |

### 2.3 时间参数、心跳与超时约定

| 项目 | 规定值 | 责任方与行为约定 |
| --- | --- | --- |
| **心跳发送周期** | `2000 ms`（2 s） | 上位机建连后每 `2 s` 发送一次 `system.heartbeat`。心跳处理独立于业务工作流锁，不触发拍照或运动、不报 `BUSY`；**标定运动等待期间上位机也须持续发送心跳** |
| **链路断线判定** | `6000 ms`（6 s） | 任一方连续 `6 s` 未收到对端任何有效报文（心跳、业务请求、应答或推送均刷新活跃计时）即判定连接断开并主动关闭套接字，由上位机重连 |
| **`system.ack` 应答超时** | `1000 ms` | 上位机发送 `system.hello` / `system.heartbeat` 后等待 `system.ack` 的超时上限（视觉内存直回，典型 `< 10 ms`） |
| **`inspection.result` 应答超时** | `3000 ms` | 上位机发送 `inspection.trigger` 后等待回复的超时上限。视觉典型生产 CT 为 `80 ~ 250 ms`（6 连板），正常工况最大耗时 `≤ 1500 ms`；视觉生产单次采图超时收紧至 `≤ 2000 ms`，确保端到端 `≤ 2500 ms` 内必有应答（正常结果或错误） |
| **`calibration.started.ack` 应答超时** | `3000 ms` | 视觉发送 `calibration.started` 后等待上位机确认及锁存原点的超时上限；超时后视觉终止本次启动，不下发任何 `move.request` |
| **单点标定运动超时** | `30000 ms`（默认，可配置） | 视觉发送 `calibration.move.request` 后等待 `motion.arrived` 或 `motion.failed` 的超时上限；若上位机发生异常应立即回 `motion.failed`，不要等待超时 |

### 2.4 数值精度与 R 轴角度坐标系

- **数值精度**：
  - **机械坐标（mm）**：四舍五入保留 **3 位小数**（精度 `0.001 mm`），涵盖 `x`、`y`、`originX`、`originY`、`offsetX`、`offsetY`、`machineX`、`machineY`、`stepX`、`stepY`。
  - **机械角度（deg）**：四舍五入保留 **3 位小数**（精度 `0.001 deg`），涵盖 `r`、`originR`、`offsetR`、`machineR`、`stepR`、`currentRLeft`、`currentRRight`、`currentR`、`rOffset`、`targetR`、`pickR`、`blindPlaceR`。
  - **图像与统计量**：像素坐标与图像角常规保留 2~3 位小数，匹配分数 `score` 保留 3 位小数，耗时 `elapsedMilliseconds` 保留 1 位小数，分辨率 `resolutionX` / `resolutionY` 保留 6 位小数。
  - 报文传输使用标准 JSON number，解析方按浮点数解析，不依赖文本末尾补零个数。
- **R 轴角度不做归一化（连续坐标系）**：
  - 视觉输出的 `rOffset`、`targetR`、`pickR`、`blindPlaceR` **不做 `[-180, 180]` 或 `[0, 360]` 截断归一化**，严格保持与输入 `currentRLeft` / `currentRRight` 相同的连续角度坐标系：
    - `Left.targetR = currentRLeft + Left.rOffset`
    - `Right.targetR = currentRRight + Right.rOffset`
  - 目标角度是否超出 R1 / R2 轴软限位或多圈行程，由上位机统一判定与处理。
- **错误码命名规范**：全协议所有错误码（`system.error.data.code`、`inspection.result.data.errorCode`、`calibration.completed.data.errorCode`、`motion.failed.data.code`）统一采用**全大写下划线格式（`UPPER_SNAKE_CASE`）**，成功无错误统一为 `"NONE"`。

## 3. 业务交互流程

### 3.1 连接握手、心跳保活与状态推送

- 建连后上位机发 `system.hello`，视觉回 `system.ack`（返回当前 `ready`、各模块使能与相机连接状态）。
- 上位机每 `2 s` 发送 `system.heartbeat`，视觉在 `1000 ms` 内回 `system.ack`；任一方连续 `6 s` 未收到有效报文即判定断线。
- 连接保持期间，当视觉端**相机使能、相机连接状态、标定使能、标定就绪状态或检测使能**任一项发生变化时，视觉主动推送 `system.status`（上位机无需应答）。

```text
上位机 (Client)                              视觉工作站 (Server:9100)
      |                                                |
      |----------- TCP Connect ----------------------->|
      |----------- system.hello ---------------------->|
      |<---------- system.ack -------------------------| (返回 ready、各开关及协议版本 1.1)
      |                                                |
      |----------- system.heartbeat ------------------>| (每 2s 发送，不触发拍照/运动)
      |<---------- system.ack -------------------------| (1000ms 内应答；6s 无报文断线)
      |                                                |
      |<========== system.status ======================| (使能或相机状态变化时主动推送)
```

### 3.2 双吸嘴独立 9 + 5 标定流程

- **双吸嘴独立标定方案**：左吸嘴（`nozzle="Left"`, `axisR="R1"`）与右吸嘴（`nozzle="Right"`, `axisR="R2"`）**分别独立执行一次完整的 9+5（14 点）标定会话**，并分别保存各自的标定文件与求解结果（各自独立的旋转中心、旋转方向系数及 XY 映射矩阵），避免两吸嘴物理安装偏置及高度差引入误差。
- **点位规划**：每次会话共 14 个点。点 `1..9` 为 3×3 蛇形平移网格（点 `5` 为平移零偏移原点）；点 `10..14` 为指定 `axisR` 轴的旋转点（`-2dR, -dR, 0, +dR, +2dR`，其中点 `12` 与点 `5` 共用同一个标定会话原点）。
- **会话握手与原点锁存**：
  1. 标定开始前，视觉先发 `calibration.started`（携带唯一 `sessionId`、`nozzle`、`axisR`、`totalPoints`、`stepX/Y/R`）。
  2. 上位机检查设备是否处于可标定状态（非生产中、已回原、无急停/安全门报警等）：
     - 允许标定：进入标定模式，**立即锁存此时刻实测绝对位置 `(originX, originY, originR)`**（`originR` 为对应 `axisR` 的当前实测绝对角），回复 `calibration.started.ack(accepted=true)`；
     - 拒绝标定：回复 `calibration.started.ack(accepted=false, reason=...)`，视觉不下发任何 `move.request`，并在界面显示 `reason`。
  3. 本会话内每条 `calibration.move.request` 均携带 `sessionId` 和 `axisR`。上位机统一按 `目标绝对位 = (originX + offsetX, originY + offsetY, originR + offsetR)` 驱动 X/Y 与对应 `axisR` 运动（禁止相对上一点累加）。
- **到位反馈、拒动与中止**：
  - 正常到位并完全停稳后，上位机回 `motion.arrived`（携带实测绝对 `(x, y, r)`）；视觉随后软触发拍照、模板定位并通知 `calibration.point.result`。
  - 若目标超软限位、急停、安全门打开、伺服报警或会话不匹配，上位机**立即回 `motion.failed`**；视觉立即终止本会话，不再拍照或下发后续点位，直接发送 `calibration.completed(success=false, errorCode="MOTION_FAILED")`。
  - 标定进行中，上位机可随时发 `calibration.cancel` 主动中止；视觉立即停止下发并回 `calibration.completed(success=false, errorCode="CANCELLED")`。
  - 操作员在视觉界面点击“停止标定”或关闭标定/相机开关导致中止时，视觉同样主动发送 `calibration.completed(success=false, errorCode="CANCELLED")`，以便上位机退出标定模式。
- **旧标定结果保护**：任何中止、拒绝、运动失败、超时、断线或求解失败均**不得用半途数据覆盖**该吸嘴原有已生效的标定结果。

```text
上位机 (Client)                              视觉工作站 (Server)
      |                                                |
      |<-- calibration.started (sessionId, nozzle, axisR, stepX/Y/R) --|
      |  [检查互锁与标定条件；若允许则锁存原点 (originX,originY,originR)] |
      |--- calibration.started.ack (accepted, originX/Y/R, reason) --->|
      |    (若 accepted=false，流程直接结束，视觉界面提示 reason)         |
      |                                                |
      |<-- calibration.move.request (sessionId, axisR, pt, offset) ----|
      |  [驱动 X/Y 与 axisR 至 origin + offset 并等待停稳]              |
      |                                                |
      |  [分支 A：正常到位停稳]                          |
      |--- motion.arrived (corrId, sessionId, pt, 实测XYR) ----------->|
      |                                                | [软触发拍照 -> 模板定位]
      |<-- calibration.point.result (sessionId, axisR, pt, status) ----|
      |             ... (点 1 ~ 点 14) ...              |
      |<-- calibration.completed (success=true, errorCode="NONE") -----|
      |                                                |
      |  [分支 B：上位机运动异常/拒动]                    |
      |--- motion.failed (corrId, sessionId, pt, code, message) ------>|
      |<-- calibration.completed (success=false, "MOTION_FAILED") -----| (保留旧标定)
      |                                                |
      |  [分支 C：上位机主动中止]                        |
      |--- calibration.cancel (sessionId, reason) -------------------->|
      |<-- calibration.completed (success=false, "CANCELLED") ---------| (保留旧标定)
      |                                                |
      |  [分支 D：视觉界面点击“停止标定”]                |
      |<-- calibration.completed (success=false, "CANCELLED") ---------| (保留旧标定)
```

### 3.3 生产实时检测流程

- **使能前提**：视觉端“启用检测”与“启用相机”必须开启且真实相机已连接；“启用标定”保持独立，未开启标定（或尚未完成左/右标定与示教）时仍可执行视觉定位与瑕疵检测：空料返回 `NO_MATERIAL`（`pass=true`），有板时返回 `COORDINATE_NOT_MAPPED`（`executed=true, success=false, pass=false, coordinateMapped=false, items[].valid=false, targets=[]`）。
- **双 R 轴独立映射**：上位机在 `inspection.trigger` 中同时传入拍照时刻的 `currentRLeft`（R1）与 `currentRRight`（R2）。视觉侧分别使用左吸嘴（R1）与右吸嘴（R2）各自保存的旋转中心、旋转方向及示教基准，独立计算每块板的 `Left (axis="R1")` 与 `Right (axis="R2")` 目标坐标和角度。
- **空料工况（正常工况）**：视野内未定位到任何 PCB（`actualCount == 0` 且定位引擎运行正常）时，返回 `executed=true, success=true, pass=true, errorCode="NO_MATERIAL", items=[]`，上位机按空料正常继续自动流程，不报警停机。
- **数量不一致工况**：定位到 `actualCount >= 1` 但 `actualCount != expectedCount` 时，返回 `executed=true, success=false, pass=false, errorCode="BOARD_COUNT_MISMATCH"`，并**仍完整返回全部已定位板件的 `items`（含坐标、角度、`hasManualMark` 与单板 `valid`）**，由上位机结合操作员确认决定按实际数量继续取料或停止清料。
- **排序约定**：返回的 `items` 中 `boardIndex` 从 `1` 连续编号至 `actualCount`，严格按图像空间**从上到下分行、同行内从左到右**固定排序；上位机不得按 `score` 重新排序。

```text
上位机 (Client)                              视觉工作站 (Server)
      |  [皮带到位停稳，同步采集当前 R1/R2 角度]         |
      |--- inspection.trigger (currentRLeft, currentRRight, expectedCount) -->|
      |                                                | [软触发拍照 -> 多板定位 -> Blob -> 双R映射]
      |<-- inspection.result (NONE / NO_MATERIAL / MANUAL_MARK_FOUND / BOARD_COUNT_MISMATCH) --|
```

## 4. 指令与数据格式明细

### 4.1 上位机发送给视觉（Host -> Vision）

#### (1) `system.hello` — 建连握手

```json
{
  "version": "1.1",
  "messageId": "host-hello-0001",
  "correlationId": null,
  "type": "system.hello",
  "timestampUtc": "2026-11-23T08:00:00.000Z",
  "data": {
    "role": "host",
    "station": "ZM910A-01",
    "capabilities": ["motion-xy-r1r2", "calibration-session-v1.1", "dual-r-inspection"]
  }
}
```

#### (2) `system.heartbeat` — 心跳保活

建连后每 `2 s` 发送一次。

```json
{
  "version": "1.1",
  "messageId": "host-hb-0002",
  "correlationId": null,
  "type": "system.heartbeat",
  "timestampUtc": "2026-11-23T08:00:02.000Z",
  "data": {}
}
```

#### (3) `calibration.started.ack` — 标定会话确认与原点锁存（v1.1 新增）

回复视觉发出的 `calibration.started`。

```json
{
  "version": "1.1",
  "messageId": "host-cal-start-ack-0001",
  "correlationId": "vision-cal-start-0001",
  "type": "calibration.started.ack",
  "timestampUtc": "2026-11-23T08:00:10.050Z",
  "data": {
    "sessionId": "cal-20261123-0001",
    "accepted": true,
    "originX": 650.120,
    "originY": 210.450,
    "originR": 0.000,
    "reason": ""
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 是 | 须与对应 `calibration.started.data.sessionId` 一致 |
| `accepted` | bool | 是 | `true` 表示已进入标定模式并锁存原点；`false` 表示拒绝开始标定 |
| `originX` | number | `accepted=true` 时必填 | 本会话锁存的原点实测绝对 X 坐标（mm，3 位小数，有限数值） |
| `originY` | number | `accepted=true` 时必填 | 本会话锁存的原点实测绝对 Y 坐标（mm，3 位小数，有限数值） |
| `originR` | number | `accepted=true` 时必填 | 本会话锁存的对应 `axisR` 实测绝对角度（deg，3 位小数，有限数值） |
| `reason` | string | `accepted=false` 时必填 | 拒绝原因（如 `"Machine in production"`, `"Axis not homed"`, `"Emergency stop active"`），视觉将在界面展示该原因 |

#### (4) `motion.arrived` — 标定运动到位反馈

回复视觉发出的 `calibration.move.request`（正常到位停稳时发送）。

```json
{
  "version": "1.1",
  "messageId": "host-arrived-0003",
  "correlationId": "vision-move-req-uuid",
  "type": "motion.arrived",
  "timestampUtc": "2026-11-23T08:00:12.000Z",
  "data": {
    "sessionId": "cal-20261123-0001",
    "pointNumber": 1,
    "x": 640.120,
    "y": 200.450,
    "r": 0.000
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 建议（v1.1 新增） | 当前标定会话 ID；若传入且与当前会话不符，视觉将拒收并记录告警 |
| `pointNumber` | int | 是 | 标定点编号（`1..14`），须与对应 `calibration.move.request` 一致 |
| `x` | number | 是 | 停稳后实测绝对机械 X 坐标（mm，3 位小数） |
| `y` | number | 是 | 停稳后实测绝对机械 Y 坐标（mm，3 位小数） |
| `r` | number | 是 | 停稳后对应 `axisR`（R1 或 R2）实测绝对机械角度（deg，3 位小数） |

#### (5) `motion.failed` — 标定运动拒绝/异常反馈（v1.1 新增）

作为 `calibration.move.request` 的异常应答（与 `motion.arrived` 二选一），`correlationId` 须等于对应 `calibration.move.request.messageId`。视觉收到后立即终止当前标定会话，不再拍照、不再下发后续点位，下发 `calibration.completed(success=false, errorCode="MOTION_FAILED")`，并保留原有标定结果。

```json
{
  "version": "1.1",
  "messageId": "host-motion-fail-0004",
  "correlationId": "vision-move-req-uuid",
  "type": "motion.failed",
  "timestampUtc": "2026-11-23T08:00:18.120Z",
  "data": {
    "sessionId": "cal-20261123-0001",
    "pointNumber": 7,
    "code": "SOFT_LIMIT",
    "message": "Target X 905.000 exceeds soft limit 900.000"
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 是 | 当前标定会话 ID |
| `pointNumber` | int | 是 | 失败对应的标定点编号（`1..14`） |
| `code` | string | 是 | 标准错误码（全大写下划线，见第 4.3.5 节） |
| `message` | string | 是 | 现场可读的详细原因，视觉记录日志并透传至 `calibration.completed.message` 与界面提示 |

#### (6) `calibration.cancel` — 上位机主动中止标定（v1.1 新增）

由上位机在标定会话期间主动发起（`correlationId` 为 `null` 或 `""`）。视觉收到后立即停止下发后续点位、取消在途等待、保留旧标定结果不被半途数据覆盖，并回复 `calibration.completed(success=false, errorCode="CANCELLED")`（`correlationId` 填本请求的 `messageId`）。

```json
{
  "version": "1.1",
  "messageId": "host-cal-cancel-0005",
  "correlationId": null,
  "type": "calibration.cancel",
  "timestampUtc": "2026-11-23T08:00:25.000Z",
  "data": {
    "sessionId": "cal-20261123-0001",
    "reason": "Operator stop"
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | string | 是 | 要中止的标定会话 ID |
| `reason` | string | 建议 | 中止原因（如 `"Operator stop"`, `"Safety door opened"`） |

#### (7) `inspection.trigger` — 生产检测触发（v1.1 支持双 R 轴）

```json
{
  "version": "1.1",
  "messageId": "host-insp-0006",
  "correlationId": null,
  "type": "inspection.trigger",
  "timestampUtc": "2026-11-23T08:01:00.000Z",
  "data": {
    "currentRLeft": 12.500,
    "currentRRight": -3.200,
    "expectedCount": 6,
    "archiveImage": false
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `currentRLeft` | number | **条件必填** | 拍照时刻左吸嘴 R1 轴绝对角度（deg，3 位小数，有限数值）；当视觉开启标定且标定/示教就绪时与 `currentRRight` **同时必填** |
| `currentRRight` | number | **条件必填** | 拍照时刻右吸嘴 R2 轴绝对角度（deg，3 位小数，有限数值）；与 `currentRLeft` 成对提供 |
| `currentR` | number | 否（仅 v1.0 兼容） | 旧版单 R 轴兼容字段。当 `currentRLeft` 与 `currentRRight` 均存在时以双值为准并忽略 `currentR`；若仅传 `currentR`（未传双值），左右两轴均回退采用 `currentR` |
| `expectedCount` | int | 否 | 期望 PCB 板数量（需 `> 0`）；省略时采用视觉工作站默认配置（默认 `6`） |
| `archiveImage` | bool | 否 | 是否归档本帧检测图像；省略时沿用视觉工作站默认配置 |

**角度参数校验规则**：
- 若 `currentRLeft` 与 `currentRRight` 只传了其中之一，或任意角度字段为非有限数值（`NaN` / `Infinity` / 非法数字），直接返回 `system.error / PROTOCOL_INVALID`（`retryable=false`）。
- 启用标定且标定/示教就绪时，若双值与兼容字段 `currentR` 均未提供，返回 `system.error / PROTOCOL_INVALID`。
- 纯视觉检测模式（标定开关关闭，或标定/示教尚未就绪）下，可省略角度字段（默认 `0.000`），仍正常返回定位与瑕疵判定：空料返回 `NO_MATERIAL`（`pass=true`）；有板时返回 `COORDINATE_NOT_MAPPED`（`executed=true, success=false, pass=false, coordinateMapped=false, items[].valid=false, targets=[]`）。

#### (8) `teaching.submit` — 提交机械坐标并触发远程示教（v1.1 补全）

上位机将板放到示教位并将吸嘴移开不遮挡相机后发送，视觉软触发拍照（`≤ 2000 ms`）、锁定第 1 号基准板并保存至 `teaching.json`（应答超时建议 `3000 ms`）。

```json
{
  "version": "1.1",
  "messageId": "host-teach-0001",
  "correlationId": null,
  "type": "teaching.submit",
  "timestampUtc": "2026-11-23T09:00:00.000Z",
  "data": {
    "nozzle": "Left",
    "axisR": "R1",
    "x": 650.120,
    "y": 210.450,
    "r": 0.000
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `nozzle` / `axisR` | string | 是 | `"Left"/"R1"` 或 `"Right"/"R2"`（两者若同时传须一致） |
| `x` / `y` / `r` | number | 是 | 放板至示教位时该吸嘴的实测机械坐标（mm / deg，3 位小数，有限数值） |

```json

  "correlationId": null,

  "timestampUtc": "2026-11-23T08:00:10.000Z",

```

| `data` 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 本次标定会话全局唯一 ID（如 `cal-yyyyMMdd-xxxx`） |
| `nozzle` | string | 本次标定的目标吸嘴：`"Left"` 或 `"Right"` |
| `axisR` | string | 本次标定驱动的 R 轴标识：`"R1"`（对应 `Left`）或 `"R2"`（对应 `Right`） |
| `totalPoints` | int | 本次标定总点数，9+5 流程固定为 `14` |
| `stepX` / `stepY` | number | 平移步距（mm，3 位小数），便于上位机预先评估软限位行程（平移范围 `±stepX` / `±stepY`） |
| `stepR` | number | 旋转步距（deg，3 位小数），便于上位机预先评估 R 轴行程（旋转范围 `±2*stepR`） |

#### (6) `calibration.completed` — 标定汇总完成/中止通知（v1.1 新增 `sessionId`、`nozzle`、`axisR`，统一大写错误码）

在以下所有结束路径下视觉均发送本消息，上位机收到后即可安全退出标定模式：
1. 14 点采集完毕并求解完成（成功或求解失败）；
2. 收到上位机 `motion.failed`（`errorCode="MOTION_FAILED"`）；
3. 收到上位机 `calibration.cancel`（`errorCode="CANCELLED"`，`correlationId` 等于该 `calibration.cancel.messageId`）；
4. 视觉界面点击“停止标定”或开关关闭中止（`errorCode="CANCELLED"`，`correlationId=null`）；
5. 单点运动等待超时（`errorCode="MOTION_TIMEOUT"`）。

```json

}
```

| `data` 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 对应的标定会话 ID（v1.1 新增） |
| `nozzle` | string | 对应的吸嘴 `"Left"` 或 `"Right"`（v1.1 新增） |
| `axisR` | string | 对应的 R 轴 `"R1"` 或 `"R2"`（v1.1 新增） |
| `success` | bool | 本次标定是否成功并已保存生效；`false` 时旧标定结果保持不变 |
| `errorCode` | string | **全大写下划线错误码**（v1.1 统一，原 `"None"` 改为 `"NONE"`，详见第 4.3.4 节） |

| `rmsResidualPixels` | number | 标定像素残差 RMS（px）；未求解或失败时为 `0.0` |

| `matchElapsedMilliseconds` | number | 模板定位耗时（ms） |
| `blobElapsedMilliseconds` | number | 逐板 Blob 分析耗时（ms） |

| `items[].hasManualMark` | bool | **该单块板**是否检出人工标记（在 `BOARD_COUNT_MISMATCH`、`COORDINATE_NOT_MAPPED` 或单板 `valid=false` 时同样独立分析给出且**完全可信**） |

| `items[].targets[].axis` | string | 对应的独立 R 轴标识：Left 固定 `"R1"`，Right 固定 `"R2"`（v1.1 新增） |
| `items[].targets[].x` / `y` | number | 映射后的目标机械 XY 坐标（mm，3 位小数，含板旋转及对应吸嘴旋转中心补偿） |
| `items[].targets[].rOffset` | number | 相对该侧当前 R 轴的角度补偿增量（deg，3 位小数） |
| `items[].targets[].targetR` | number | 补偿后的该侧目标 R 轴绝对角（deg，3 位小数）：Left 按 `currentRLeft + Left.rOffset` 计算，Right 按 `currentRRight + Right.rOffset` 计算；不做归一化 |
| `items[].targets[].pickR` | number | 相对该侧 R 轴及独立示教基准计算的对齐来料吸取角（deg，3 位小数，不做归一化） |
| `items[].targets[].blindPlaceR` | number | 相对该侧 R 轴及独立示教基准计算的盲摆回正放置角（deg，3 位小数，不做归一化） |

**空料（`NO_MATERIAL`）判定依据与误判风险说明**：
- **判定依据**：在启用模板匹配且定位模板有效的前提下，相机正常抓图并由 HALCON 多目标模板匹配引擎（`LocateAll`）在设定的搜索区域（SearchRegion 或全图）内按 `MinScore` 与角度范围执行搜索。当**匹配引擎执行完全正常**（无模型损坏、无参数非法、无算子异常、无非法 NaN/Infinity 位姿）且**有效匹配结果数为 `0`** 时，判定为视野内无 PCB 来料，返回 `NO_MATERIAL`；只要定位到至少 `1` 块板（`actualCount >= 1`），严禁返回 `NO_MATERIAL`。
- **与 `POSITIONING_FAILED` 的严格区分**：只有定位引擎运行异常、模板模型失效或返回非法位姿时才返回 `POSITIONING_FAILED`（`success=false, pass=false`）。
- **误判风险评估与建议措施**：若实际有料但发生**光源熄灭/严重过曝欠曝、镜头严重遮挡、料盘严重偏移出搜索区或混入错误型号产品（错料）**，导致所有板件匹配得分均低于 `MinScore`，匹配数也会为 `0` 而输出 `NO_MATERIAL`。建议现场采取以下联合防护：
  1. 视觉端保持光源与固定曝光稳定，按实测得分分布合理设定 `MinScore` 并覆盖完整来料搜索区；
  2. 上位机可结合**皮带光电/到料传感器**复核：若光电判定有料但视觉返回 `NO_MATERIAL`（或连续多次空拍），可触发“疑似错料/光源异常”提示。

**数量不一致（`BOARD_COUNT_MISMATCH`）返回约束**：
- 当 `actualCount >= 1` 且 `actualCount != expectedCount` 时，`executed=true, success=false, pass=false, errorCode="BOARD_COUNT_MISMATCH"`。
- `items` 必须完整保留全部 `1..actualCount` 块已成功定位板件的 `boardIndex`、`valid`、`row/column/angle/score`、`hasManualMark` 以及 `targets`（含 Left/R1 与 Right/R2 完整坐标与角度）。是否按实际数量继续取料或人工清料，由上位机与操作员决策。

#### (8) `teaching.result` — 远程示教结果回复（对应 `teaching.submit`）

### 4.3 错误码规范与返回类型边界清单

#### 4.3.1 触发失败返回类型边界规则

为消除上位机解析二义性，统一按以下边界区分 `system.error` 与 `inspection.result`：

- **未进入检测流程**（协议/字段校验失败、消息去重、未知消息类型、功能使能开关关闭、真实相机未连接、工作流忙、通信框架未捕获异常）→ **一律返回 `system.error`**。
- **已进入检测流程**（含模板/标定/示教/ROI/期望板数等工艺配置校验失败、图像获取失败、空料、数量不符、人工标记、定位/Blob/算法内部异常）→ **一律返回 `inspection.result`**（前置工艺校验失败时 `executed=false`，已执行采图检测后 `executed=true`）。

#### 4.3.2 `system.error.data.code` 全量清单

| 错误码 | `retryable` | 触发场景 | 含义与上位机处理方式 |
| --- | --- | --- | --- |
| `PROTOCOL_INVALID` | `false` | `inspection.trigger` 等 | 请求字段缺失或类型/数值非法（如双 R 仅传单侧、含 `NaN`/`Infinity`、标定就绪时未传任何 R 角）；**禁止重试**，排查报文构造 |
| `INSPECTION_DISABLED` | `false` | `inspection.trigger` | 视觉端“启用检测”开关已关闭；**禁止自动重试**，需报警由操作员开启 |
| `CAMERA_DISABLED` | `false` | `inspection.trigger` | 视觉端“启用相机”开关已关闭；**禁止自动重试**，需报警由操作员开启 |
| `CAMERA_NOT_CONNECTED` | `true` | `inspection.trigger` | 视觉端真实相机尚未连接或掉线；待收到 `system.status(cameraConnected=true)` 或相机恢复后可使用新 `messageId` 重试 |
| `CALIBRATION_DISABLED` | `false` | 标定相关请求 | 视觉端“启用标定”开关已关闭；**禁止自动重试** |
| `BUSY` | `true` | `inspection.trigger` 等 | 视觉正在执行其他标定/检测/示教任务；可稍后使用新 `messageId` 重试 |
| `DUPLICATE_MESSAGE` | `false` | 任意请求 | 同一次 TCP 连接内 `messageId` 重复，不会重复执行业务 |
| `MESSAGE_TYPE_UNSUPPORTED` | `false` | 任意请求 | 未支持的报文 `type` |
| `INTERNAL_ERROR` | `true` | 任意请求 | 通信分发或框架层发生未分类异常 |

#### 4.3.3 `inspection.result.data.errorCode` 全量清单

| 错误码 | `executed` | `success` | `pass` | `items` 内容 | 含义与上位机处理建议 |
| --- | --- | --- | --- | --- | --- |

### 6.2 上机联调仍待上位机确认项

1. **坐标系与正方向**：确认机械 X/Y/R1/R2 的正方向定义与视觉标定验证一致。
2. **R 轴运动模式**：确认生产取料采用 `targetR` 直接补偿，还是采用 `pickR`（对齐板角吸取）+ `blindPlaceR`（盲摆回正放置）模式。
3. **NG 与清料策略**：确认单板检出人工标记（`pass=false`、`items[].hasManualMark=true`）时按单板跳过或整盘停机，以及结合皮带光电对连续 `NO_MATERIAL` 的异常告警阈值。
4. **后续扩展指令**：确认是否需要后续版本新增 TCP **产品配方切换**或**远程启动自动标定**指令（远程示教 `teaching.submit` 已并入 v1.1 正式版）。
