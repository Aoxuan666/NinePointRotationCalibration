# 视觉工作站上位机 TCP 通讯接口规范

> 协议版本：v1.0  
> 适用系统：视觉工作站（TCP Server） <-> 上位机控制系统（TCP Client）

---

## 1. 通讯架构与职责边界

| 角色 | 通讯身份 | 职责范围 |
| --- | --- | --- |
| **视觉工作站** | TCP Server（默认监听 `0.0.0.0:9100`，单客户端连接） | 相机控制与取图、模板定位、9+5 标定求解、PCB 瑕疵检测、左右吸嘴目标坐标与角度映射 |
| **上位机** | TCP Client | X/Y/R 轴运动控制、到位停稳判定、安全互锁、吸取/贴装动作执行与整机报警处理 |

---

## 2. 传输与报文协议（标准 JSON 格式）

### 2.1 帧格式与编码

- **TCP 帧结构**：`[4 字节无符号大端整数 N] + [N 字节 UTF-8 JSON 数据]`
- **最大帧长**：默认 `1 MiB (1048576 字节)`。长度为 `0`、超限、非合法 UTF-8 或 JSON 格式错误时，服务端将直接断开连接。
- **数值与时间**：所有数字使用标准 JSON 数值（小数点固定为 `.`），时间戳采用 UTC ISO-8601 格式。

### 2.2 统一消息包络

所有收发报文均采用统一的 JSON 包络格式：

```json
{
  "version": "1.0",
  "messageId": "6f26388d0d214fbd9c8a37a6dd434270",
  "correlationId": "",
  "type": "inspection.trigger",
  "timestampUtc": "2026-11-18T08:00:00.0000000Z",
  "data": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `version` | string | 是 | 协议版本号，固定为 `"1.0"` |
| `messageId` | string | 是 | 发送方生成的唯一消息 ID。同一次 TCP 连接内不可重复，重复发送会返回 `DUPLICATE_MESSAGE`；失败重试必须重新生成新 ID |
| `correlationId` | string/null | 条件必填 | **所有应答和结果报文必填**，值须等于对应请求报文的 `messageId`；主动发起的请求或通知可为 `""` 或 `null` |
| `type` | string | 是 | 消息类型（统一小写点分格式） |
| `timestampUtc` | string | 建议 | UTC ISO-8601 时间戳 |
| `data` | object | 是 | 业务数据体，无字段时传 `{}` |

## 3. 业务交互流程

### 3.1 连接握手与心跳保活

```text
上位机 (Client)                              视觉工作站 (Server:9100)
      |                                                |
      |----------- TCP Connect ----------------------->|
      |----------- system.hello ---------------------->|
      |<---------- system.ack -------------------------| (返回 ready 与使能状态)
      |                                                |
      |----------- system.heartbeat ------------------>| (周期发送，不触发拍照或运动)
      |<---------- system.ack -------------------------|
```

### 3.2 9 + 5 标定流程（视觉请求运动，上位机回传实测坐标）

- **点位规划**：共 14 个点。点 `1..9` 为 3×3 蛇形平移网格（点 `5` 为会话原点）；点 `10..14` 为旋转点（`-2dR, -dR, 0, +dR, +2dR`，其中点 `12` 与点 `5` **共用同一个标定原点**）。
- **坐标规则**：视觉发送的 `offsetX / offsetY / offsetR` 均为**相对于本次标定会话原点的绝对偏移量**（不可相对上一点递增累加）。
- **时序约束**：上位机必须等待机构移动到位并**完全停稳**后，将**实际读回的绝对机械坐标 `(x, y, r)`** 通过 `motion.arrived` 返回给视觉，且必须在超时时间内（默认 `30000 ms`）回传关联正确的 `correlationId`。

```text
上位机 (Client)                              视觉工作站 (Server)
      |                                                |
      |<-- calibration.move.request (点号, 相对偏移) ---|
      |  [运动至目标位并等待机械停稳]                    |
      |--- motion.arrived (correlationId, 实测XYR) --->|
      |                                                | [软触发拍照 -> 模板定位]
      |<-- calibration.point.result (单点定位与状态) ---|
      |             ... (点 1 ~ 点 14) ...              |
      |<-- calibration.completed (标定求解汇总) --------|
```

### 3.3 生产实时检测流程

- **使能前提**：视觉端“相机使能”与“标定使能”必须同时开启；任一关闭时，触发请求会直接返回 `CAMERA_DISABLED` 或 `CALIBRATION_DISABLED`（不可重试）。
- **排序约定**：返回的 `items` 中 `boardIndex` 从 `1` 开始，严格按图像空间**从上到下分行、同行内从左到右**固定排序；上位机不得按匹配分数 `score` 重新排序。

```text
上位机 (Client)                              视觉工作站 (Server)
      |  [产品到位停稳，采集当前 R 轴角度 currentR]      |
      |--- inspection.trigger (currentR, 板数) ------->|
      |                                                | [软触发拍照 -> 定位 -> Blob -> 映射]
      |<-- inspection.result (pass/NG, 每板左右目标) ---|
```

## 4. 指令与数据格式明细

### 4.1 上位机发送给视觉（Host -> Vision）

#### (1) `system.hello` — 建连握手

```json
{
  "version": "1.0",
  "messageId": "host-hello-0001",
  "correlationId": null,
  "type": "system.hello",
  "timestampUtc": "2026-11-18T08:00:00Z",
  "data": {
    "role": "host",
    "station": "mounter-01",
    "capabilities": ["motion-xyr"]
  }
}
```

#### (2) `system.heartbeat` — 心跳保活

```json
{
  "version": "1.0",
  "messageId": "host-hb-0002",
  "correlationId": null,
  "type": "system.heartbeat",
  "timestampUtc": "2026-11-18T08:00:05Z",
  "data": {}
}
```

#### (3) `motion.arrived` — 标定运动到位反馈

回复视觉发出的 `calibration.move.request`。

```json
{
  "version": "1.0",
  "messageId": "host-arrived-0003",
  "correlationId": "vision-move-req-uuid",
  "type": "motion.arrived",
  "timestampUtc": "2026-11-18T08:00:12Z",
  "data": {
    "pointNumber": 1,
    "x": 102.345,
    "y": 55.120,
    "r": -10.0
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pointNumber` | int | 是 | 标定点编号（`1..14`），须与对应的 `calibration.move.request` 一致 |
| `x` | number | 是 | 停稳后实测绝对机械 X 坐标（mm） |
| `y` | number | 是 | 停稳后实测绝对机械 Y 坐标（mm） |
| `r` | number | 是 | 停稳后实测绝对机械 R 角度（deg） |

#### (4) `inspection.trigger` — 生产检测触发

```json
{
  "version": "1.0",
  "messageId": "host-insp-0004",
  "correlationId": null,
  "type": "inspection.trigger",
  "timestampUtc": "2026-11-18T08:01:00Z",
  "data": {
    "currentR": 12.5,
    "expectedCount": 6,
    "archiveImage": false
  }
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `currentR` | number | **是** | 拍照时刻当前机械 R 轴绝对角度（deg），必须为有限数值；缺失或非法将返回 `PROTOCOL_INVALID` |
| `expectedCount` | int | 否 | 期望 PCB 板数量；省略时采用视觉工作站默认配置（默认 `6`） |
| `archiveImage` | bool | 否 | 是否归档本帧检测图像；省略时沿用视觉工作站默认配置 |

---

### 4.2 视觉发送给上位机（Vision -> Host）

#### (1) `system.ack` — 系统应答（对应 `system.hello` / `system.heartbeat`）

```json
{
  "version": "1.0",
  "messageId": "vision-ack-0001",
  "correlationId": "host-hello-0001",
  "type": "system.ack",
  "timestampUtc": "2026-11-18T08:00:00.015Z",
  "data": {
    "role": "vision",
    "ready": true,
    "cameraEnabled": true,
    "calibrationEnabled": true,
    "protocolVersion": "1.0"
  }
}
```

| `data` 字段 | 类型 | 说明 |
| --- | --- | --- |
| `role` | string | 固定 `"vision"` |
| `ready` | bool | 相机已连接且相机/标定开关均启用时为 `true` |
| `cameraEnabled` | bool | 相机使能开关当前状态 |
| `calibrationEnabled` | bool | 标定与坐标换算开关当前状态 |
| `protocolVersion` | string | 协议版本号 `"1.0"` |

#### (2) `calibration.move.request` — 标定运动请求

```json
{
  "version": "1.0",
  "messageId": "vision-move-req-uuid",
  "correlationId": null,
  "type": "calibration.move.request",
  "timestampUtc": "2026-11-18T08:00:10.000Z",
  "data": {
    "pointNumber": 1,
    "kind": "translation",
    "coordinateMode": "calibration-origin-relative",
    "offsetX": -10.0,
    "offsetY": -10.0,
    "offsetR": 0.0,
    "sharedOrigin": false,
    "replyType": "motion.arrived"
  }
}
```

| `data` 字段 | 类型 | 说明 |
| --- | --- | --- |
| `pointNumber` | int | 标定点编号（`1..14`） |
| `kind` | string | `"translation"`（点 1..9）或 `"rotation"`（点 10..14） |
| `coordinateMode` | string | 固定 `"calibration-origin-relative"`，目标绝对坐标 = `标定原点(X0,Y0,R0) + (offsetX, offsetY, offsetR)` |
| `offsetX` / `offsetY` / `offsetR` | number | 相对标定会话原点的目标偏移量（mm / deg） |
| `sharedOrigin` | bool | 点 `5` 与点 `12` 为 `true`（共用零偏移原点），其余点为 `false` |
| `replyType` | string | 期望上位机回复 `"motion.arrived"` |

#### (3) `calibration.point.result` — 标定单点结果通知

`correlationId` 等于对应点 `calibration.move.request.messageId`。若上位机运动反馈超时，`success=false`、`status="Failed"`，`message` 以 `"MOTION_TIMEOUT:"` 开头。

```json
{
  "version": "1.0",
  "messageId": "vision-pt-res-0001",
  "correlationId": "vision-move-req-uuid",
  "type": "calibration.point.result",
  "timestampUtc": "2026-11-18T08:00:12.120Z",
  "data": {
    "pointNumber": 1,
    "success": true,
    "status": "Completed",
    "machineX": 102.345,
    "machineY": 55.120,
    "machineR": -10.0,
    "imageRow": 1012.44,
    "imageColumn": 812.31,
    "imageAngle": 0.18,
    "score": 0.91,
    "message": "Captured"
  }
}
```

#### (4) `calibration.completed` — 标定汇总完成通知

```json
{
  "version": "1.0",
  "messageId": "vision-cal-done-0001",
  "correlationId": null,
  "type": "calibration.completed",
  "timestampUtc": "2026-11-18T08:01:00.000Z",
  "data": {
    "success": true,
    "errorCode": "None",
    "message": "Calibration succeeded.",
    "resolutionX": 0.0152,
    "resolutionY": 0.0152,
    "rmsResidualPixels": 0.18
  }
}
```

#### (5) `inspection.result` — 生产检测结果（对应 `inspection.trigger`）

```json
{
  "version": "1.0",
  "messageId": "vision-insp-res-0004",
  "correlationId": "host-insp-0004",
  "type": "inspection.result",
  "timestampUtc": "2026-11-18T08:01:00.085Z",
  "data": {
    "executed": true,
    "success": true,
    "pass": false,
    "errorCode": "MANUAL_MARK_FOUND",
    "message": "Manual white mark detected.",
    "expectedCount": 6,
    "actualCount": 6,
    "hasManualMarks": true,
    "currentR": 12.5,
    "elapsedMilliseconds": 83.7,
    "matchElapsedMilliseconds": 55.2,
    "blobElapsedMilliseconds": 21.4,
    "items": [
      {
        "boardIndex": 1,
        "row": 430.2,
        "column": 812.6,
        "angle": -1.8,
        "score": 0.94,
        "hasManualMark": true,
        "targets": [
          {
            "side": "Left",
            "x": 120.1,
            "y": 30.2,
            "rOffset": -0.6,
            "targetR": 11.9,
            "pickR": 10.7,
            "blindPlaceR": 0.0
          },
          {
            "side": "Right",
            "x": 142.3,
            "y": 30.0,
            "rOffset": -0.6,
            "targetR": 11.9,
            "pickR": 10.7,
            "blindPlaceR": 0.0
          }
        ]
      }
    ]
  }
}
```

| 字段路径 | 类型 | 说明 |
| --- | --- | --- |
| `executed` | bool | 检测流程是否实际执行（缺失模板/标定等前置条件时为 `false`） |
| `success` | bool | 定位是否执行成功且实测板数等于期望板数（`actualCount == expectedCount`） |
| `pass` | bool | **最终工艺放行判定**（`success && !hasManualMarks`）。检出人工白标记时 `success=true` 且 `pass=false` |
| `errorCode` / `message` | string | 结果状态码及描述（见第 4.3 节） |
| `expectedCount` / `actualCount` | int | 期望板数 / 实际定位板数 |
| `hasManualMarks` | bool | 是否存在任意一块板检出白色人工坏板标记 |
| `currentR` | number | 回显本次触发传入的 R 轴角度（deg） |
| `elapsedMilliseconds` | number | 视觉检测总耗时（ms） |
| `matchElapsedMilliseconds` | number | 模板定位耗时（ms） |
| `blobElapsedMilliseconds` | number | 逐板 Blob 分析耗时（ms） |
| `items[].boardIndex` | int | 板序号（从 1 开始，按空间从上到下分行、同行从左到右编号） |
| `items[].row` / `column` / `angle` / `score` | number | 该板模板定位中心像素坐标、图像角（deg）及匹配分数 |
| `items[].hasManualMark` | bool | **该单块板**是否检出人工白标记 |
| `items[].targets[].side` | string | `"Left"` 或 `"Right"` |
| `items[].targets[].x` / `y` | number | 映射后的目标机械 XY 坐标（mm，含板旋转及偏心旋转中心补偿） |
| `items[].targets[].rOffset` | number | 相对 `currentR` 的角度补偿增量（deg） |
| `items[].targets[].targetR` | number | 补偿后的目标 R 轴角度（`currentR + rOffset`，deg） |
| `items[].targets[].pickR` | number | 吸取对齐来料板角时的 R 轴角度（deg） |
| `items[].targets[].blindPlaceR` | number | 示教基准固定放置角（用于盲摆回正放置，deg） |

#### (6) `system.error` — 系统级错误

```json
{
  "version": "1.0",
  "messageId": "vision-err-0001",
  "correlationId": "host-insp-0004",
  "type": "system.error",
  "timestampUtc": "2026-11-18T08:01:00.002Z",
  "data": {
    "code": "CAMERA_DISABLED",
    "message": "Production inspection is unavailable because camera use is disabled.",
    "retryable": false
  }
}
```

### 4.3 错误码规范

#### `system.error.data.code`

| 错误码 | `retryable` | 含义与上位机处理方式 |
| --- | --- | --- |
| `PROTOCOL_INVALID` | `false` | 请求字段缺失或类型非法（如 `currentR` 非有限数值） |
| `CAMERA_DISABLED` | `false` | 视觉端“启用相机”已关闭；**禁止自动重试**，需报警由操作员开启 |
| `CALIBRATION_DISABLED` | `false` | 视觉端“启用标定与坐标换算”已关闭；**禁止自动重试**，需报警由操作员开启 |
| `BUSY` | `true` | 视觉正在执行其他标定/检测/示教任务；可稍后使用新 `messageId` 重试 |
| `DUPLICATE_MESSAGE` | `false` | 同连接内 `messageId` 重复 |
| `MESSAGE_TYPE_UNSUPPORTED` | `false` | 未知的报文 `type` |
| `INTERNAL_ERROR` | `true` | 视觉处理请求时发生未分类异常 |

#### `inspection.result.data.errorCode`

| 错误码 | 含义 |
| --- | --- |
| `NONE` | 检测完成，板数正确且无人工坏板标记（`success=true, pass=true`） |
| `MANUAL_MARK_FOUND` | 板数正确，但检出白色人工标记（`success=true, pass=false`） |
| `BOARD_COUNT_MISMATCH` | 实际定位板数与 `expectedCount` 不相等（`success=false, pass=false`） |
| `POSITIONING_TEMPLATE_MISSING` | 未配置或未加载 PCB 定位模板 |
| `CALIBRATION_MISSING` | 九点 XY 标定或旋转标定结果不可用 |
| `TEACHING_MISSING` | 左或右吸嘴示教数据不完整 |
| `CURRENT_R_INVALID` | 传入 `currentR` 非有限数值 |
| `DETECTION_PROFILE_INVALID` | 检测参数配置无效 |
| `DETECTION_ROI_MISSING` | 定位模板未配置模板 ROI 或检测 ROI |
| `EXPECTED_COUNT_INVALID` | 期望板数 ≤ 0 |
| `POSITIONING_FAILED` | PCB 模板定位失败 |
| `BLOB_ANALYSIS_FAILED` | Blob 分析未为每块板返回结果 |
| `IMAGE_MISSING` | 未获得检测图像 |
| `INSPECTION_EXCEPTION` | 检测算法内部异常 |

## 5. 备选协议：纯 String 行文本格式（如上位机不解析 JSON 时采用）

若上位机侧不便解析 4 字节包头及 JSON，可双方约定采用以下纯文本协议：

### 5.1 帧与定界规则

- **字符编码与帧结束符**：UTF-8 字符串，**每条指令以 `\r\n`（CRLF）结尾**。
- **分隔符**：
  - `,`：顶层参数分隔；
  - `|`：检测结果头信息与多板列表分隔；
  - `;`：多板列表内各板分隔。
- **固定包头**：每条指令前 3 个字段固定为 **`指令字,seqId,corrId`**（`seqId` 为发送方唯一流水号；应答时 `corrId` 填对方请求的 `seqId`，主动发起填 `0`）。
- **布尔表示**：`1` 表示 `true`，`0` 表示 `false`；消息描述文本中不含 `\r`、`\n`、`,`、`;`、`|`。

### 5.2 上位机 -> 视觉（String 指令）

| 用途 | 指令格式 | 示例 |
| --- | --- | --- |
| 握手 | `HELLO,<seqId>,0,<role>,<station>\r\n` | `HELLO,1001,0,host,mounter-01\r\n` |
| 心跳 | `HB,<seqId>,0\r\n` | `HB,1002,0\r\n` |
| 标定到位 | `ARRIVED,<seqId>,<corrId>,<pointNumber>,<actualX>,<actualY>,<actualR>\r\n` | `ARRIVED,1003,5001,1,102.345,55.120,-10.000\r\n` |
| 生产触发 | `TRIG,<seqId>,0,<currentR>[,<expectedCount>[,<archive01>]]\r\n` | `TRIG,1004,0,12.500,6,0\r\n` |

### 5.3 视觉 -> 上位机（String 返回）

| 用途 | 返回格式 | 示例 |
| --- | --- | --- |
| 系统应答 | `ACK,<seqId>,<corrId>,<ready01>,<camEn01>,<calEn01>,<protoVer>\r\n` | `ACK,9001,1001,1,1,1,1.0\r\n` |
| 标定运动请求 | `MOVE,<seqId>,0,<pointNumber>,<kindT/R>,<offsetX>,<offsetY>,<offsetR>,<sharedOrigin01>\r\n` | `MOVE,5001,0,1,T,-10.000,-10.000,0.000,0\r\n` |

## 6. 上机联调确认项（需上位机确认）

1. **协议格式确认**：采用 **第 4 节 JSON 协议（v1.0）** 或 **第 5 节纯 String 文本协议**。
2. **网络与端口**：视觉工作站监听 `0.0.0.0:9100`，上位机作为 Client 主动连接并维持单连接。
3. **坐标系与单位**：确认 X/Y 单位（默认 `mm`）、R 轴单位（默认 `deg`）、各轴正方向定义及 R 轴角度归一化区间。
4. **标定原点与停稳延时**：确认标定开始前上位机定位至原点位置保持不变，机械完全停稳后再回复 `motion.arrived / ARRIVED`。
5. **R 轴运动模式**：确认生产取料采用 `targetR` 直接补偿，还是采用 `pickR`（对齐板角吸取）+ `blindPlaceR`（回正放置）模式。
6. **NG 策略**：确认单板检出人工标记（`pass=false`、`items[].hasManualMark=true`）时按单板跳过或整盘停机，以及 `BOARD_COUNT_MISMATCH` 的报警与清料逻辑。
7. **扩展指令需求**：确认是否需要新增 TCP 触发**左右示教**、**产品配方切换**或**远程启动自动标定**指令（当前版本该三项在视觉工作站界面操作）。
