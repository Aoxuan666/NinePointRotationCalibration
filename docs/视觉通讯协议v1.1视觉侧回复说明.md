## 二、逐项详细回复

### 事项一：有板但未做坐标映射时明确判为不放行（`COORDINATE_NOT_MAPPED`）

- **现状核查**：视觉原实现中，当 `calibrationEnabled=false` 或 `calibrationReady=false` 时会以 `mapTargets=false` 执行检测；若定位到 ≥ 1 块板且板数一致、无人工标记，确会返回 `errorCode="NONE"`、`success=true`、`pass=true`，且 `items[].targets=[]`。上位机指出的“有板 `pass=true` 却无取料坐标”问题属实。
- **修订规则**：
  1. `inspection.result.data.errorCode` 新增 **`COORDINATE_NOT_MAPPED`**。
  2. 触发条件：`actualCount ≥ 1` 且 `coordinateMapped=false`（且未触发更高优先级的 `BOARD_COUNT_MISMATCH`）。
  3. 返回字段：`executed=true`、`success=false`、`pass=false`、`coordinateMapped=false`。`items` 仍完整返回每块板的 `boardIndex`、`row`、`column`、`angle`、`score` 与 `hasManualMark`，并将 `items[].valid=false`、`items[].targets=[]`。
  4. **空料不受影响**：`actualCount=0` 且定位引擎正常时，仍返回 `NO_MATERIAL`（`executed=true, success=true, pass=true, items=[]`）。
- **响应示例**：

```json
"data": {
  "executed": true,
  "success": false,
  "pass": false,
  "coordinateMapped": false,
  "errorCode": "COORDINATE_NOT_MAPPED",
  "message": "检测已完成，但标定未启用，未生成取料坐标（OK 6 / NG 0）",
  "expectedCount": 6,
  "actualCount": 6,
  "hasManualMarks": false,
  "items": [
    {
      "boardIndex": 1,
      "valid": false,
      "row": 430.20,
      "column": 812.60,
      "angle": -1.80,
      "score": 0.940,
      "hasManualMark": false,
      "targets": []
    }
  ]
}
```

### 事项二：单板 `valid=false` 整帧不放行、5 级优先级与 `hasManualMark` 可信性

- **现状核查**：原实现仅将该板置 `valid=false`（`targets=[]`），整帧仍可能返回 `NONE` / `pass=true`。
- **修订规则**：
  1. `inspection.result.data.errorCode` 新增 **`COORDINATE_MAPPING_FAILED`**：板数与期望一致、已执行坐标映射（`coordinateMapped=true`），但至少 1 块板 `valid=false`。此时返回 `executed=true`、`success=false`、`pass=false`，`items` 完整返回全部板件（异常板 `valid=false, targets=[]`，正常板保留有效坐标与目标）。
  2. **硬性规则**：**只要任一块板 `valid=false`，整帧 `pass` 必为 `false`**。
  3. **有板（`actualCount ≥ 1`）错误码 5 级优先级（从高到低）**：

| 优先级 | `errorCode` | 条件 | `executed` | `success` | `pass` |
| --- | --- | --- | --- | --- | --- |
| 1 | `BOARD_COUNT_MISMATCH` | `actualCount ≥ 1` 且 `≠ expectedCount` | `true` | `false` | `false` |
| 2 | `COORDINATE_NOT_MAPPED` | 板数一致，且 `coordinateMapped=false` | `true` | `false` | `false` |
| 3 | `COORDINATE_MAPPING_FAILED` | 板数一致、`coordinateMapped=true`，但存在 `valid=false` | `true` | `false` | `false` |
| 4 | `MANUAL_MARK_FOUND` | 板数一致、坐标全部有效，存在 `hasManualMark=true` | `true` | `true` | `false` |
| 5 | `NONE` | 板数一致、坐标全部有效、无人工标记 | `true` | `true` | `true` |

- **关于 `valid=false` 板的 `hasManualMark` 是否可信（明确确认：完全可信）**：
  - 在视觉检测引擎（`BoardInspectionService.InspectCore`）中，执行顺序严格为：**整帧多板模板定位 → 按固定行列规则排序编号 → 基于像素模板/检测 ROI 独立执行逐板 Blob 人工标记分析 → 最后执行机械坐标映射**。
  - 坐标映射异常（如仿射溢出或单侧目标缺失）仅影响该板的 `valid` 与 `targets` 字段，**完全不影响**该板的模板匹配得分、像素坐标/角度及 `hasManualMark` 判定。同理，在 `COORDINATE_NOT_MAPPED` 场景下，每块板的 `hasManualMark` 同样完整执行且**完全可信**。

### 事项三：示教坐标来源说明与新增 `teaching.submit` / `teaching.result`

1. **原 v1.1 示教坐标获取方式说明**：
   - 在原 v1.1 界面示教流程中，工作站“左右示教”页的机械 `X / Y / R` 确实需要操作员**手工录入**文本框，再点击“记录当前”触发拍照定位；确实存在人工输错导致整批偏移的风险。
2. **新增远程示教协议（已按上位机建议方案实现）**：
   - 新增 **上位机 → 视觉 `teaching.submit`** 与 **视觉 → 上位机 `teaching.result`**（`correlationId = teaching.submit.messageId`）。
   - **前置校验边界**：若 `CalibrationEnabled=false` 返回 `system.error / CALIBRATION_DISABLED`（`retryable=false`）；`CameraEnabled=false` 返回 `CAMERA_DISABLED`（`retryable=false`）；相机未连返回 `CAMERA_NOT_CONNECTED`（`retryable=true`）；字段缺失、`nozzle`/`axisR` 不一致或坐标非有限数值返回 `PROTOCOL_INVALID`（`retryable=false`）；视觉工作流忙返回 `BUSY`（`retryable=true`）。
   - **采图与应答超时**：示教单次采图超时收紧至 **`≤ 2000 ms`**，确保上位机在 **`3000 ms`** 超时窗内必收到 `teaching.result` 或 `system.error`。
   - **基准板稳定性**：与界面示教共用 `TeachingService`，在一拍多板治具下按“从上到下、从左到右”稳定锁定第 1 号基准板，避免左右吸嘴示教锁定到不同子板。
   - **旧示教保护**：仅当拍照、模板匹配、持久化写入 `teaching.json` 全部成功后才原子更新内存与界面显示（`success=true, errorCode="NONE"`）；若发生任何错误（`POSITIONING_TEMPLATE_MISSING`、`CAMERA_CAPTURE_FAILED`、`MATCH_FAILED`、`TEACHING_SAVE_FAILED`、`INTERNAL_ERROR`），返回 `success=false` 并**完整保留原有 `teaching.json` 示教数据不被覆盖**。
   - **状态同步顺序**：当 `teaching.submit` 成功并导致 `calibrationReady` 状态变更（例如左、右标定与双侧示教均已齐备使 `calibrationReady` 变为 `true`）时，视觉工作站严格保证**先发出 `teaching.result(success=true)`，随后立即主动推送 `system.status`**。

- **请求与成功/失败报文**：

```json
{
  "version": "1.1",
  "messageId": "host-teach-0001",
  "correlationId": null,
  "type": "teaching.submit",
  "timestampUtc": "2026-11-23T09:00:00.000Z",
  "data": {
    "nozzle": "Left",
    "axisR": "R1",
    "x": 650.120,
    "y": 210.450,
    "r": 0.000
  }
}
```

```json
{
  "version": "1.1",
  "messageId": "vision-teach-res-0001",
  "correlationId": "host-teach-0001",
  "type": "teaching.result",
  "timestampUtc": "2026-11-23T09:00:00.180Z",
  "data": {
    "nozzle": "Left",
    "axisR": "R1",
    "success": true,
    "errorCode": "NONE",
    "message": "Teaching saved.",
    "machineX": 650.120,
    "machineY": 210.450,
    "machineR": 0.000,
    "imageRow": 1024.15,
    "imageColumn": 1280.42,
    "imageAngle": 0.12,
    "score": 0.952
  }
}
```

| `teaching.result.data.errorCode` | `success` | 旧示教保护 | 说明 |
| --- | --- | --- | --- |
| `NONE` | `true` | 更新生效 | 示教定位成功并已保存至 `teaching.json` |
| `POSITIONING_TEMPLATE_MISSING` | `false` | **保留旧示教** | PCB 定位模板未配置或模型为空 |
| `CAMERA_CAPTURE_FAILED` | `false` | **保留旧示教** | 示教拍照失败或采图超时（`> 2000 ms`） |
| `MATCH_FAILED` | `false` | **保留旧示教** | 示教基准板定位模板匹配失败 |
| `TEACHING_SAVE_FAILED` | `false` | **保留旧示教** | `teaching.json` 持久化写入失败 |
| `INTERNAL_ERROR` | `false` | **保留旧示教** | 示教执行过程中发生未分类异常 |

> 视觉工作站界面“左右示教”页的手工录入按钮仍保留作为本地调试/应急兜底手段；生产推荐由上位机统一通过 `teaching.submit` 下发机械坐标。
