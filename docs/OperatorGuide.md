# 视觉工作站操作与联调指南

## 1. 开发环境

- Visual Studio 2019，安装“.NET 桌面开发”和 .NET Framework 4.7.2 Developer Pack。
- 解决方案：`NinePointRotationCalibration.sln`。
- 运行目标固定为 x64。建议在 VS 工具栏选择 `Debug | x64`。
- HALCON 托管库默认从 `lib\halcondotnet.dll` 引用；真实模板定位还需安装匹配的 HALCON 19.11 x64 运行时并配置许可。
- 大华模式需 MV Viewer/IMV x64 运行时和相机驱动。编译时会依次查找 `lib\Dahua\x64\MVSDK_Net.dll` 和 `C:\Program Files\HuarayTech\MV Viewer\Development\DOTNET DLL\IMV\DOTNET_4.0\x64\MVSDK_Net.dll`。

## 2. 打开设计器

1. 用 VS2019 打开 `NinePointRotationCalibration.sln`。
2. 在“解决方案资源管理器”中展开 `NinePointRotationCalibration.Station > Views`。
3. 右键 `MainForm.cs`，选择“查看设计器”。

`MainForm` 使用无参数构造，设计时不启动 TCP、不连相机，也不进入 HALCON 模板流程。如果设计器仍报引用错误，先确认 4.7.2 目标包及 `lib\halcondotnet.dll` 可用，然后重新生成 Station 项目。

## 3. 生成与运行

1. 将 `NinePointRotationCalibration.Station` 设为启动项目。
2. 生成解决方案，然后按 `F5` 运行。
3. Debug 可执行文件默认位于 `src\NinePointRotationCalibration.Station\bin\Debug\NinePointRotationCalibration.Station.exe`。

也可在 Developer PowerShell 中生成：

```powershell
msbuild .\NinePointRotationCalibration.sln /t:Build /p:Configuration=Debug /p:Platform=x64 /m
```

首次运行会在可执行文件同级的 `data` 目录创建 `station.json`。默认使用 Mock 相机，TCP Server 监听 `0.0.0.0:9100`。窗口显示后始终启动监听；“启用相机”打开时还会自动枚举并连接保存的设备。

## 4. Mock 与大华相机

### Mock

Mock 是默认模式，会生成包含 6 块板、白色标记和矩形标签的测试图。可用它先验证图像窗口、模板、TCP 和业务流程。

### Dahua

1. 在“相机”页把“相机驱动”改为“大华 (CameraDH)”。
2. 点“应用参数”或“通信 / 文件 > 保存全部设置”，然后重启工作站。驱动类型只在启动时生效。
3. 重启后先看顶部相机状态点；绿色表示已自动连接。只有自动连接失败时才需点“枚举”，选择正确设备后点“连接”。
4. 设置曝光和超时，点“应用参数”，再用“测试拍照”确认软触发和取图。

如果第一次切到大华后自动连接失败，可能是 `station.json` 中仍保留 Mock 设备 ID；重新枚举、选择真实序列号并保存即可。切回 Mock 也需保存后重启。

### 自动连接与状态点

相机使能打开时，启动顺序是“TCP 监听 -> 枚举相机 -> 连接保存的序列号（未保存则第一台）-> 设置曝光 -> 启动预览”。无需每次启动后手动点“连接”。连接失败不会退出程序，可修正网卡/IP/序列号后重新枚举连接。

窗口顶部的相机圆点：绿色为已连接，黄色为连接中，红色为连接异常，灰色为未连接或相机已停用。圆点旁文字会显示设备或错误详情。关闭“启用相机”会停止预览并断开设备；再次打开会立即尝试自动连接。

TCP 使用同样的独立状态点：灰色表示未监听，黄色表示正在监听并等待上位机，绿色表示上位机已连接。将鼠标停在 TCP 状态文字上可查看监听地址或连接详情。顶部不再显示“九点标定与 PCB 视觉检测”大标题，只保留运行状态和常用操作。

### 运行模式

| 启用相机 | 启用标定与坐标换算 | 用途 |
| --- | --- | --- |
| 是 | 是 | 正常生产、9+5 标定、左右示教，检测输出左右 XY/R |
| 否 | 是 | 导入历史图复测；已有标定和示教有效时仍可核对映射坐标 |
| 是 | 否 | 用实时拍到的当前图调定位/ROI/Blob，检测结果不含机械坐标 |
| 否 | 否 | 完全离线调试定位/ROI/Blob，检测结果不含机械坐标 |

两个开关保存在 `station.json`。停用标定不会删除已有标定 Job 或示教数据；它只禁止标定、示教和坐标换算，离线视觉检测仍可运行。重新打开后继续使用原有文件。

## 5. 推荐操作顺序

### 5.1 准备文件和标定模板

1. 在“通信 / 文件”页确认标定 Job、定位 Job、示教 JSON、检测 JSON 和图像归档目录，点“保存全部设置”。要换新路径时，先保存路径，再创建模板。
2. 用实际标定特征拍一张清晰图像。
3. 进入“模板 > 标定模板”，点“创建模板”，在弹出编辑器中设置区域和匹配参数后确认。
4. 点“测试”，确认图像上的匹配点、角度和分数。重新创建标定模板会清空旧标定样本。

### 5.2 9 + 5 标定

标定必须已连接上位机。视觉只发送相对标定原点的移动请求；上位机完成运动和停稳后，必须回送实际绝对 X/Y/R。

- 点 1..9 是 3 x 3 平移点，点 5 是原点。
- 点 10..14 是 `-2dR, -dR, 0, +dR, +2dR`，点 12 与点 5 共用同一原点定义。
- 手动：设好 X/Y/R 步距，点“手动标定”，然后依次点 1..14。每个点会经历移动、拍照、定位，并在表格显示机械坐标和图像坐标。全部完成后点“计算并保存”。
- 自动：点“自动标定”，工作站会依次请求 14 个点，并在最后自动计算。上位机必须对每个 `calibration.move.request` 单独回复关联正确的 `motion.arrived`。

当前标定“稳定时间”由上位机负责：只有机构停稳后才可发 `motion.arrived`。页面上的“稳定等待”数值当前不会额外延时。

### 5.3 定位模板与左右示教

1. 放入可代表生产状态的 PCB，拍照后在“模板 > 定位模板”点“创建模板”。
2. 在“定位模板与检测区域”编辑器中完成板件模板后，点“检测区”并在同一张参考图上拖出检测 ROI；切回“选择”后，可拖动 ROI 内部移动、拖动控制点缩放、拖动旋转手柄改变角度。检测 ROI 与定位模板一起保存在定位 Job 中，不在检测页重复维护一套几何数值。
3. 保存后点“测试”，确认多目标定位数和分数。
4. 用上位机把机构移到左侧示教位，在“左右示教”页输入当前实际机械 X/Y/R，点左侧“记录当前”。
5. 对右侧重复上一步。记录时工作站会自行拍照并用定位模板求图像位姿，不需要上位机再触发一次拍照。

### 5.4 检测 ROI 与试运行

1. 在“检测”页设置目标板数、阈值、目标极性、Blob 面积范围、矩形度和“启用矩形标签过滤”。黑底白点保持“白底黑点”关闭；白底黑点时打开该选项。
2. “使用模板中的检测 ROI（随板旋转）”打开时，系统读取定位 Job 中保存的检测 ROI，并按每个模板匹配结果的中心和角度分别变换。定位到 N 块板就生成 N 个随板移动、旋转的检测区域。
3. 关闭该选项时，不使用自定义检测 ROI；系统对每个匹配板分别使用其定位模板区域的轴对齐外接矩形。定位到 N 块板同样生成 N 个独立检测区域，而不是在整张图上共用一个固定区域。
4. 点“保存参数”。检测页保存阈值、面积、过滤和 ROI 使用模式；ROI 的位置、尺寸和角度只随定位 Job 保存。
5. 手动测试时输入拍照时的“当前 R”，点“测试检测”。图像上会显示每块板实际使用的检测区域，界面可核对实际板数、白叉/白点、板号和是否生成 L/R 映射。板号应先从上到下分行，同行内从左到右，不随匹配分数变化；左右 X/Y、`rOffset` 和 `targetR` 数值在 TCP `inspection.result.items[].targets` 中联调确认。
6. 生产时由上位机发 `inspection.trigger`；工作站回 `inspection.result`。`success` 表示检测执行且板数正确，`pass` 才是工艺 OK/NG；检出人工白标记时会出现 `success=true, pass=false`。

### 5.5 Blob 二值化调试

1. 先导入图片或拍照，再进入“检测”页点“Blob 调试”。调试窗口会锁定当前图像，不会触发相机或替换主窗口的检测帧。
2. 窗口中的“局部二值图”页显示每个检测 ROI 的完整阈值分割，而不是只显示最终保留的最大连通域。黑底白点显示为黑底白目标，白底黑点显示为白底黑目标；ROI 外保持黑色。修改阈值、目标极性、面积、矩形度或过滤开关后，预览会在短暂防抖后更新，旧计算结果会自动丢弃。
3. 默认启用模板匹配。关闭“启用模板匹配”后，窗口对整幅图直接二值化和 Blob 分析，适合没有定位模板时快速确认阈值；此模式不生成板件机械坐标。
4. 确认无误后点“应用参数”，窗口关闭并返回检测页，参数一次性保存。取消或关闭窗口不会修改检测页参数。

生产流程默认始终启用模板匹配；整图直通模式用于离线/调试，不应作为 `inspection.trigger` 的生产配方。

### 5.6 不连接相机时导图检测

1. 在“相机”页关闭“启用相机”。若只想检查板件定位、数量和白叉/白点，同时关闭“启用标定与坐标换算”。
2. 点图像区上方“导入图片”，选择一张常见格式的本地图像。导入只更新当前图，不会枚举、连接或触发相机。
3. 确认已加载或创建包含检测 ROI 的 PCB 定位模板，并在“检测”页设置目标板数、阈值、Blob 面积、矩形标签过滤和 ROI 使用模式。若关闭“使用模板中的检测 ROI”，则不要求定位 Job 含有自定义检测 ROI，系统会使用每块板的模板外接矩形。
4. 点“检测当前图”。结果表和 Overlay 会显示板号、定位姿态及人工标记判断。
5. 标定使能关闭时，只校验视觉结果，每块板的 `targets` 为空，不输出 XY、`rOffset` 或 `targetR`。标定使能打开时，必须已有有效 XY/R 标定和左右示教，才能对导入图计算映射坐标。

导入图只用于本机调试，不参与 TCP 生产请求，也不会被后续 `inspection.trigger` 复用。要测试另一张图必须重新导入。

## 6. TCP 联调检查表

1. 上位机作为 Client 连接视觉机 IP 的 `9100` 端口；视觉端同时只接受一个 Client。
2. 每帧使用“4 字节无符号大端 JSON 长度 + UTF-8 JSON”，默认上限 1 MiB。
3. 先发 `system.hello` 或 `system.heartbeat`，确认收到 `system.ack` 且 `correlationId` 正确。
4. 每个 `messageId` 在当前连接内唯一；重试时使用新 ID。
5. 标定时核对 `calibration.move.request -> motion.arrived -> calibration.point.result`。`motion.arrived.correlationId` 必须等于移动请求 ID，且 `x/y/r` 是停稳后实际绝对值。
6. 检测时 `inspection.trigger.currentR` 必填且为有限数值，核对回复中的板数、`success/pass`、每块板两侧目标以及 `rOffset/targetR`。`boardIndex` 从 1 开始，必须稳定遵循“从上到下分行、同行从左到右”，不按 `score` 排序。
7. 相机关闭时生产触发返回 `system.error / CAMERA_DISABLED`；相机打开但标定关闭时返回 `system.error / CALIBRATION_DISABLED`。两者都关闭时优先返回 `CAMERA_DISABLED`，且这些错误均不可重试。
8. 同时发起两个视觉流程会收到 `BUSY`。坏帧、非 UTF-8 或非法 JSON 会导致连接被断开。

更完整的消息示例和错误码见 `docs\TcpProtocolV1.md`。TCP 地址或端口修改后必须保存并重启工作站，仅停止/启动监听不会重建运行时服务。

## 7. 数据文件

默认位于 `<程序目录>\data`：

| 文件 | 用途 |
| --- | --- |
| `station.json` | 相机/标定使能、TCP、相机、标定步距、期望板数和其他路径 |
| `calibration.nprcal` | 标定模板、14 点样本及求解所需数据 |
| `positioning.nprcal` | PCB 定位模板及在模板编辑器中设置的检测 ROI |
| `teaching.json` | 左/右示教图像位姿和机械位姿 |
| `detection-profile.json` | 模板匹配开关、ROI 使用模式、亮度和 Blob/矩形过滤参数；不再单独保存 ROI 几何 |
| `images\` | 按配置或 `archiveImage=true` 保存的生产图像 |

## 8. 现场仍需确认

- 上位机 X/Y/R 的单位、正方向、R 轴角度范围和归一化规则。
- 点 5/点 12 共用原点在一次标定会话中的建立、保留和失效时机。
- 上位机发 `motion.arrived` 前的到位容差、稳定时间和超时处理。
- 实机大华相机的序列号、IP/网卡配置、像素格式、曝光、触发稳定性与连续取图压力。
- 黑板/蓝板、白叉/白点、矩形标签的现场样本阈值，以及板边缘、反光和局部遮挡时的稳定性。
- 左/右示教点的物理定义和输出顺序，并用正反旋转样件确认 `rOffset` 符号。
- 目标数不符、人工标记、模板定位失败时，上位机的报警、停机、重试和清料策略。
- 心跳周期、断线重连、请求超时、日志/图像保留周期和磁盘容量。
- HALCON 许可、大华 native runtime 以及真实硬件环境下的整机长时验证。
- 四种使能组合、自动连接失败恢复、导图检测不触发相机，以及禁用模式 TCP 错误码。
